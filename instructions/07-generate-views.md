# Step 7. Generate the views

**Goal:** the three forms of access are generated from the records, with corrections applied: `docs/` for people, JSONL and the Python API for code, and `agent/` for LLMs.

**Standard:** §6 (derived properties and annotations), §7 (generated views and completeness labels).

## Do

1. **Derived properties** come from named, versioned rules, such as `scale_signature_from_valid_labels`. The build writes them to `metadata/derived/<property>.jsonl` (today each repo's build has its own copy of the rule; the standard puts them in the shared library). They support `complete_by_rule` results. Topic tags and aliases are annotations (`metadata/annotations/`, any origin) and only ever support `approximate` results.
2. **Publisher subject lists are groups** of kind `subject` (§5.1), not annotations. gssrdoc's subjects became 23 subject groups in the GSS slice.
3. **Run `make views`**, which runs `pdt views .`, from the dataset repo. It writes `agent/` (index, `SKILL.md`, shards by release/table, group, subject and scale signature) and `docs/`. Never edit the output.
4. **Rerun it after every build.** The views carry a hash of their inputs, and C8 fails when they're stale.

## Check before moving on

- [ ] `agent/index.md` reads correctly for this dataset: the description, the terms, what a wave and a form are, and each release's waves.
- [ ] **A structural query and a topic query work.** Run `pdt search` with:
  - a filter you can check by hand, such as `{"available": {"wave": W, "form": F}}` or a subject;
  - and look for the label you expect: `complete` for publisher fields, `complete_by_rule` when a rule is involved.

  Task 23's answer keys and harness in [`eval/`](../eval/) show how to test this with an agent.
- [ ] **Corrected fields show as corrected** in the line form (`*`) and on the docs page.
- [ ] `pdt check` passes, including C8 once it's implemented.

## Using a finished repo

An agent that *uses* the repo (finding variables, reporting completeness) follows the generated `agent/SKILL.md`, for example [`pdt-gss/agent/SKILL.md`](../../pdt-gss/agent/SKILL.md). It is generated by `pdt views`, so it stays in step with the library. Improve it by changing [`lib/pdt/views.py`](../lib/pdt/views.py), not by writing a second version.
