# Working in this repo

PublicDataToolkit holds instructions and agent skills for turning a public dataset into a well-documented repository. The resulting repository publishes the dataset's metadata in three forms: human-readable, programmable, and LLM access. See [`README.md`](README.md).

`PROJECT_BOARD.md` holds the numbered tasks and is the place to record findings and decisions. `planning/` holds the longer designs.

## Layout

```
PROPOSAL.md    the public summary for review; keep it free of internal details
STANDARD.md    what a finished dataset repo must contain; the definition of done
schema/        JSON Schemas for the records, examples, and check_examples.py
planning/      designs and context
  plan.md                            the plan (Task 1)
  data_dict.md                       note for Hadley: relationship to data-dict, questions (Task 6)
  review_1.md                        first review of PROPOSAL.md, triaged, with decisions (Task 10)
  versions_layout_names.md           versioning, CCDS, repo names (Task 8)
  inventory.md                       what exists for GSS, ANES and NSFG (Task 3)
  survey_metadata_packages_plan.md   earlier design, copied from CultureWar Task 186 (2026-11-17)
  context.md                         what was discussed at snake_case on 2026-11-19
```

More directories will come once the plan (Task 1) settles the structure.

## Rules

- **No microdata in this repo.** It holds instructions, skills and small examples. Data for a target dataset goes in that dataset's own repository, as a release or through a download script.
- **Respect each publisher's terms.** Some datasets can be redistributed and others can't. Record the terms for every dataset before shipping anything built from it.
- **Separate source facts from derived ones.** Metadata copied from the publisher, corrections to it, and anything generated by rules or models stay distinguishable and are labeled.
- **Read before changing.** Source material lives in sibling repos checked out next to this one: `../CultureWar` (the codebook layer, extract builders and inventories), `../GssExtract`, `../ExtractANES` and `../MarriageNSFG`. Read those repos, and don't modify them from here.

## Writing markdown

Plain, specific sentences. Use tables for comparisons and short lists for steps. Link to files with relative paths.
